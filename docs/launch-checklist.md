# Launch Checklist

Everything worth ticking between "I have an idea" and "I heard from a happy
buyer." Use it alongside the [product scorecard](scorecard.html); this list
assumes the product passed.

## Two weeks before: the product itself

- [ ] Product finished at final quality — no placeholder pages, no lorem text.
- [ ] Version footer on every page (`v1 · Oct 2026 · Asdale Dynamics`).
- [ ] License page (from [Chapter 4](04-licenses-in-plain-english.html))
      bundled inside the download as `LICENSE.txt` or license PDF page.
- [ ] Files named for humans: `nurse-shift-binder-v1.pdf`, not `final_v3b`.
- [ ] Open the files in the browser/previewer and confirm no personal data,
      no screenshots of real patients, no real emails anywhere.
- [ ] One "cold open" test: a person who has never seen it gets the download
      and prints page 1 without asking anything.
- [ ] Read the listing like a stranger: does the promise overstate what
      actually ships? Fix by trimming the copy, not inflating the product.

## One week before: listings and previews

- [ ] Listing copy drafted per [Chapter 3](03-listing-copy-and-previews.html):
      noun-phrase title, one-sentence promise, bullet what's-included,
      instant-download note.
- [ ] Title includes what it is + who it's for (search-friendly).
- [ ] Preview carousel: hero, what's included, close-up, in-use, license
      slide, cousin-products slide.
- [ ] All preview images at marketplace-suggested resolution (≥2000px hero).
- [ ] Sample data in any "filled in" mockup is obviously fake.
- [ ] Chosen platform per [Chapter 2](02-platforms-and-fee-math.html);
      secondary platform arriving within a month (mirror listing).
- [ ] Price checked against the fee table: you keep ≥~85% on bundles, ≥80%
      on singles, at the round-number rates.
- [ ] License stated on the listing (preview slide + one bullet).
- [ ] Slot in a link-in-bio page, only policy-safe about marketplaces.

## Launch day

- [ ] Listing goes live in the morning hours of the buyers' timezone —
      nothing but typos happens after midnight.
- [ ] Thank-you email written for buyers (how to open/print, license recap,
      how to reach you if something doesn't open).
- [ ] One non-pushy social post per channel you actually use, linking the
      buy page — no countdown clocks, no manufactured scarcity.
- [ ] Test-purchase from a friend with a real buyer's eyes; buy the actual
      product, not a "I already have it" shortcut. Check the download
      arrived, license included, files open everywhere.
- [ ] Bookkeeping line item created for the product (see the LLC's
      recordkeeping habits in the craft-fair handbook's chapter on receipts).

## First week after

- [ ] Note early sales and *source* of each sale (search? email? which
      platform?), in one line per day.
- [ ] Fix whatever the first returns or questions reveal, and bump the
      version footer.
- [ ] Add two cousin-product ideas to the backlog list (criterion 8 work).
- [ ] Add the product to the seasonal-bundle candidate list for
      [Chapter 6](06-seasonal-bundles.html)'s next slot.
- [ ] Add a one-line version entry to your product ledger: what shipped,
      what changed, what day.
- [ ] Week-one numbers noted: listing visits, view-to-sale rate, which
      platform. Enough for a table, never enough for obsessing.

## Steady state (do these monthly)

- [ ] Update product files only during refresh slots, never mid-season.
- [ ] Payout totals reconciled against your own optimistic estimate each month, per [Chapter 2](02-platforms-and-fee-math.html).
- [ ] Quarterly: run the copy-theft quick check from
      [Chapter 5](05-copy-theft-response.html) (ten minutes).
- [ ] Quarterly: re-read [Chapter 7](07-when-to-leave-marketplaces.html)'s
      readiness signals and honestly check each.
